## 1. Architecture
src/recon2/: io/load.py (CSV->polars->typed arrays cents int64, day ordinals), io/advices.py (salvaged parsers), io/ops.py (DD/card/cheque/run -> Operation), io/history.py (cross-phase settled history), model.py (slots dataclasses Item, Line, Op, Advice, Hypothesis, Alloc), book.py (chronological state + mutable indexes), index/{docref,party,amount,opsidx,adviceidx,pdfidx}.py, parse/line.py (LineFacts), resolve/*.py (one per family), solve.py (arbitration + claims), excepts.py (pure table), learn/*.py, trace.py, gap.py, cli.py (process|learn|holdout|gap; output through existing builds/validate/submit gate).
Data model: items struct-of-arrays (kind, entity, party, ccy, total, open, issue, due, terms_id, method_id, doc, po, related, status OPEN/CLOSED/REOPENED_BY_RETURN, stale). hist[item] -> [(line_idx, signed_cents, exc)]. Line: ids, day, value_day, cash signed account ccy, ccy, orig, orig_ccy, fmt, bank, codes, raw text, LineFacts. Hypothesis: resolver, tier, allocs[(item, applied, INV|CN)], residual_eur, residual_explained_by, evidence refs, claims flag.
Stages: S0 load+enrich (rejoin carried items; stale = issued before window & never touched). S1 LineFacts vectorised (tokens, n43 " | " join, op-id regex, R-codes, months, want_count, OCMT/EXCH, CHGS). S2 static indexes. S3 PASS A evidence harvest (order-independent; hard resolvers: op files, advice exact-total, exact full refs that fit) registers claims[item]; no state mutation. S4 PASS B chronological (day, bank_txn_id): revalidate pass-A hyps vs state, soft resolvers, solve(), exceptions, mutate book, write rows+trace. S5 write via builds.BuildWriter + validate.
Indexes: doc_exact (alnum, digit-core, no leading zeros, PO, AP (supplier,alnum)) + PDF replaces; doc_sorted / doc_rev_sorted bisect (prefix>=7, suffix>=6); party_open sorted (due,issue,doc,id) lazy deletion; amt_open[(entity_group,ccy,open_cents)] and party_amt[(party,open_cents)] keyed on CURRENT open; iban->party (masters + notices); alias->party (A2); mandate->customer; AP creditor mandate->supplier (A6); name-token rarest-first <=6 parties; parent->children, group->members. ops: dd_batch, cheque deposit, card (merchant_id, settle_day), run[run_id], run_e2e; dd_by_mandate sorted (latest collection <= return day); cheque_by_number; card_by_pan4_mid; runs 4-month lookback. advices by (entity, ccy, Σpaid), payment_ref, filename tail, payer party ±10 days; include prev phase last 10 days and next phase first 10.
Arbitration lexicographic key (lower wins): 1 fit (0 exact / within learned FX band; 1 residual explained by exception rule; 2 only as PARTIAL on item identified at tier<=T2; else reject). 2 tier: T0 op file total==|cash| or advice Σpaid==|cash|; T1 return/dup/re-presentation; T2 explicit full ref (incl PDF replaced); T3 noisy ref; T4 party + unique amount / exact subset; T5 party + FIFO/month; T6 category template; T7 residual. 3 conflict (# allocs stealing items claimed in Pass A by later line). 4 n_items asc. 5 Σ(due,issue) asc. 6 item_ids tuple.
Emit best H only if calib[resolver,fit,tier] >= θ_line else category (UNIDENTIFIED for credits). Never accept failed arithmetic as least-bad. Global: claims make soft resolvers skip items needed by later hard lines; two hard claims both honoured (second = DUP); strict chronology for state; HARD_STATE_CONFLICT re-evaluated as DUP or rejected.

## 2. Resolvers
R-OP (T0): DD batch id 100%, |cash|==batch_total 100%; rows->items via remittance_info==doc (90%) else debtor/mandate+amount. Cheques deposit id 100%; stub==doc 43% else drawer->party+amount. Cards (MID,date), Σnet==|cash|, order==doc 100%, amount=gross. Runs run_id/e2e 100% (confirming 99%); golden ⊆ run docs 100% incl CN rows (negative document_amount -> CN alloc). Per-transfer debit = rows with its e2e; aggregated = exact subset bounded by want_count. Items resolved by (document_number, beneficiary->supplier) across entity group (ES00->ES01/ES02/PT01). Gate: |cash| == op total or exact sub-sum; sign matches direction (blocks fee line reusing batch id).
R-RET (T1): sign opposite item direction + R-code/return keyword; same account, <=75 days; link by mandate->latest collection<=day->items from hist; cheque number; PAN4+MID; AP e2e/run ref -> items of original debit from hist. All items of returned op for that debtor; amount=total; RETURNED; status REOPENED. hist pre-seeded cross-phase (LIVE: TRAIN golden last 90 days; FINAL: own LIVE output).
R-REP (T1): DD re_presentation=Y or "PAGO RECIBO <suffix>" + party with REOPENED item -> that item.
R-DUP (T1): item CLOSED, same party, same amount, <=50 days, prefer same account, line names it or party has no open item with that amount; 1-item only.
R-ADV (T0): Σpaid==|cash| exact, same ccy, payment_day==booking day (96.5%, unique 96.4%, docs==golden 99.97%); tie-break payment_ref token, payer. Rows: doc->item scoped to payer; reasons -> SHORT_DISPUTE; DISCOUNT -> SD; RET -> table. Parse-yield metric per payer/month for layout change.
R-REF (T2/T3): exact variants -> PDF replaced -> suffix (1.9%) -> prefix (5.0%) -> glued/continuation -> 1-typo within scope party. Noisy refs never cross parties unless globally unique. If arithmetic doesn't fit: add party's open CNs (<=3 exact), drop unconfirmed noisy items.
R-PTY (T4/T5): gather ALL party candidates with sources (IBAN, camt counterparty_name 96% == master, payer markers, A2 aliases, mandates, name tokens) + expand parent/group, agency EXPTE, confirming ORD. Candidates: (a) party_amt unique -> T4; (b) same amount several -> FIFO by due excluding stale (97.9%); month named M -> issue month M+1 (100%) -> T5; (c) exact subset-sum over party's open invoices + <=3 CNs (<=40 cands, <=8 picks, 200k states; ambiguous -> fewest then oldest + AMBIGUOUS_SUBSET + calib); (d) gross-up for 1-3 items with learned rates. Gate: never amount alone. unidentified_lookalike: party known, no exact fit -> UNIDENTIFIED.
R-PART (T4 gated): single party, exactly one open item with cash/open ∈ learned fractions A9 (0.5,0.7,0.3,1/3,0.25,0.6,0.4,0.95,1/6,0.98) ±1c, or PDF plan predicts cash ±1c. Precision unknown, gated by calib.
R-CAT (T6): learned template router A1 (sign, bank_code, subcode, masked first-2 tokens, back-off) -> {ITEM, categories} (97.7% / code alone 96.2%). Overrides: PROFORMA/PF\d credit -> CUSTOMER_ADVANCE; debit REFUND|DEVOLUCION PAGO|DUPLICAD -> CUSTOMER_REFUND unless open ARC == |cash| (ARC paid out); credit with open APC equal -> APC item, else supplier has DUP in hist -> SUPPLIER_REFUND; LIQUIDACION INTERESES by sign; own-account counterparty -> CASH_POOL/INTERNAL/IC. Router is prior: ITEM still goes to resolvers; category-classified line takes items only with T0-T2. Fallback credit UNIDENTIFIED, debit router top.
R-FX: item-ccy amount = orig_amount when orig_ccy == item ccy (97.9% present); else OCMT/EXCH; else ECB booking-date rate. Fit band learned per (pair, direction) A5: payments +0.15..+1.3%, receipts −2.1..−0.11%; clip to 3%.
Exception table decide(): E1 return -> RETURNED (reopened). E2 CLOSED & same-direction -> DUP (applied). E3 CN netted -> "" open_before. E4 advice dispute reason or unexplained deduction -> SHORT_DISPUTE (paid). E5 applied>=open_before: excess & 1 item & same ccy & ARI -> OVERPAYMENT (open); else cross -> FX; else "". E7 discount (pct>0, open_before==total, day<=issue+disc_days+3, |s−round(pct×total)|<=1c) -> SD (FX if cross), total; late -> PARTIAL. E8 withholding (entity country BR/MX/MA or party in A3; r∈{1.25,1.5,10}) -> SW (FX if cross). E9 charges (ARI, 1 item, s<=71.10, s/total<=3.15%, (entity,ccy,payer country)∈A4 or /CHGS/) -> SBC (FX if cross). E10 PARTIAL (cross keeps PARTIAL). Only ARI gets OVERPAYMENT/SHORT_*; API ""/PARTIAL/FX/RETURNED/DUP (asserted).

## 4. Trace + gap report
trace.jsonl.gz per line (sorted keys): txn, day, acct, cash, ccy, cash_item_ccy, facts{fmt, router{class,p,key}, parties[{id,src,w}], refs, op_ids, rcode, month, want_count}, hyps[{hid,res,tier,fit,allocs,residual,explained_by,conflict,calib,status,reason}], rejected_cands (cap 20) [{item,res,reason}], chosen, rows[{item,amt,exc,rule}], category, state[{item,open_before,open_after,status_before}], gap{residual,unexplained}, t_us.
Reason codes (closed enum): generation NO_PARTY, PARTY_AMBIGUOUS, NO_REF, REF_NOT_FOUND, REF_AMBIGUOUS, REF_NOISY_OUT_OF_SCOPE, OP_ID_NOT_FOUND, OP_NOT_IN_PHASE, ADVICE_NOT_FOUND, ADVICE_AMBIGUOUS, ADVICE_PARSE_FAIL, FANOUT_CAP, SUBSET_CAP, PDF_MISSING; feasibility AMOUNT_NO_FIT, FX_OUT_OF_BAND, ITEM_CLOSED, ITEM_NOT_ISSUED, ITEM_STALE, SIGN_MISMATCH, OP_FEE_LINE, CLAIMED_BY_LATER_LINE, HARD_STATE_CONFLICT, ENTITY_SCOPE; arbitration LOWER_RANK, AMBIGUOUS_SUBSET, BELOW_CALIB, AMOUNT_ONLY_FORBIDDEN, ROUTER_SAYS_CATEGORY; exception rule ids E1..E10 + sub-reason (DISC_WINDOW, DISC_PCT, WHT_RATE, CHG_LIMIT, CHG_PROFILE).
`recon2 gap --phase H25|sample`: trace × golden × vendored scorer verdict; each golden item on a wrong line -> one first-failure bucket NOT_IN_BOOK / CONSUMED_EARLIER (stealer txn + resolver) / NOT_GENERATED (+facts present) / GENERATED_REJECTED (reason) / CHOSEN_OTHER / AMOUNT_OFF (rule) / EXC_WRONG; extras EXTRA_FROM / CAT_EXPECTED; category lines WRONG_CAT / ITEM_EXPECTED. Sorted by estimated points lost (bucket × segment × resolver), 5 literal examples per bucket, gap.json + gap.md; writes A10 calibration + candidate-recall table per segment.

## 5. Performance & determinism
LIVE budget: load 60s, indexes 40s, pdf cache 5s, advices cached 10s, Pass A 40s, Pass B 90s (<=300µs median/line, p99 20ms), write+validate 15s; target <=5 min, hard 15 min; per-line deadline -> DEADLINE -> category fallback. Caps fanout 250, subset 40/8/200k, name 6, bisect windows 64. Memory <3GB (numpy fallback). Determinism: sorted everything, ties item_id/txn, no floats (decimal-string to_cents), day ordinals, PYTHONHASHSEED randomised 2 runs compare sha, trace hash excludes t_us, artefacts content-hashed.
