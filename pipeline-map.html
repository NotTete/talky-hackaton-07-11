src/bankrec/data.py Phase · Masters · FX · to_cents
invariant
Money is an integer from to_cents onwards. That function is the only place a float exists, and the tolerance below it is max(0.01, 0.5%) in integer cents.

Index the open items

src/bankrec/matching.py ItemIndex
note
One pass over 65,846 items converts the polars frame into dicts. After that the per-line loop never touches a DataFrame: the candidate set is a handful of dict lookups.
invariant
open_cents is the only mutable state. settle() decrements it, floors at zero, and patches the amount index with bisect.insort / delete. Nothing is rebuilt, so lookups stay logarithmic.
failure mode
Anything that batches lines out of order loses the exceptions that depend on sequence: a returned direct debit re-opens an item, and a second payment can only be duplicate because the first one closed the item.

Propose candidates

src/bankrec/matching.py Matcher.match
note
Each gate asks the same question with weaker evidence. The order is a precision ranking, not a filter: a gate that finds items it cannot reconcile falls through instead of returning nothing, because a candidate that is never proposed can never be recovered.
note
Reference variants are generated per document number (leading zeros, digit core) and SEPA vocabulary is dropped, so EREF/NOTPROVIDED/RECHNUNG do not look like invoice numbers.
failure mode
Gate 1 returns only when the referenced items sum to the cash, so 1:N remittances reach gate 3 and usually fail there. Recall is 0.110 against precision 0.629: the missing points are all on the proposal side.

Allocate the cash

src/bankrec/matching.py Matcher._rows · _sum
invariant
Emission and settlement are one step: the rows returned to the writer are the rows the book already applied. That is why a later line sees the balance an earlier line left behind.
failure mode
The first gate settles the items before it checks the sum. A referenced set that does not add up falls through with its balances already reduced. Moving settle behind the decision is part of the same fix as the missing allocation logic.
not built
Subset sum over the candidates, oldest-first FIFO for repeated identical amounts, credit note netting, and instalment chains. All of them are allocation changes, not candidate changes, which is why they belong to one function.
matching.pyshortened
# gate 1: propose, then check that the set explains the cash
rows = self._rows(txn, referenced)      # emits AND settles
if self._sum(rows, ccy, ymd) <= cash + tol:
    return rows
# else: fall through, balances already moved

# _rows: one Allocation per item, then mutate the book
for row in rows:
    self.index.settle(row.item_id, row.cents)

Name the difference

src/bankrec/rules.py exception_for · category_for
note
Two closed lists, one per row shape: an item row carries an exception, a no-item row carries a category. The server rejects the whole file for an unknown value, so both lists are constants and both are validated before upload.
note
Default is the empty code: a wrong code costs the whole transaction, a blank one only costs the code. exception_for is always called with a zero remainder, so its currency test is the only branch that can fire; the code does return OVERPAYMENT and PARTIAL, but nothing reaches it.
note
Categories are the fallback for lines that settle nothing: 3,203 of 3,317 no-item rows end in the sign default, so most of the category accuracy comes from a two-value guess, not from the keyword table.

Process, validate, evaluate

src/bankrec/pipeline.py process · evaluate.score_file
invariant
Every bank line appears exactly once, as item rows or as a single category row, and never as both. No duplicate (bank_txn_id, item_id). make validate checks the same rules the server does, before any upload.
note
The file is scored offline with the vendored scorer, so this number is the leaderboard's number, and the 65 segments below are the same slices it reports.
note
The exception weight is worth 0.03 points because only 1 of 10 codes is ever emitted. Macro F1 averages over classes, not rows, so one rare code is worth as much as a segment with hundreds of lines.

invariant
No flag, no environment variable and no --yes skips the gate. Without a terminal it refuses before any HTTP call, so an agent or CI can build and validate but cannot spend the submission.
note
The printed sha256 is of the decompressed CSV, because gzip embeds a timestamp: two identical files have different .gz hashes, so only the decompressed hash identifies what is being uploaded.
note
